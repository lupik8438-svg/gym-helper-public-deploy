# Публикация сайта и Telegram Mini App

## Что исправлено

- Старый LocalTunnel не используется как постоянная ссылка: после остановки процесса он закономерно отдаёт `503 Tunnel Unavailable`.
- `render.yaml` теперь создаёт два сервиса: сайт и отдельный Telegram Mini App, а также одну PostgreSQL-базу для общей экосистемы.
- Добавлены `/healthz` для проверки состояния сервисов.
- Mini App открывает интерфейс сразу. Пустой профиль показывает пустые состояния, а не экран регистрации.
- Веб-страница просмотра прогресса по Telegram ID защищена ключом владельца; публичный пользователь не может получить чужие данные.

## Вход друга на сайт по телефону

- Друг открывает публичный сайт по адресу `https://gym-helper-public-site.onrender.com`.
- Нажимает **«Войти»**.
- В Telegram открывает бота и выполняет `/site` или выбирает **Управление → Код для сайта**.
- Вводит на сайте номер телефона и одноразовый шестизначный код.
- После проверки открывается личный кабинет только его пользователя.

Телефон не показывается публично и не используется для поиска чужих данных. Код действует 10 минут и используется один раз.

## Постоянный вариант

1. Создай **приватный** GitHub-репозиторий и загрузи проект без `.env` и `fitness_bot.db`.
2. В Render выбери **New → Blueprint** и подключи репозиторий.
3. Render создаст `gym-helper-public-site`, `gym-helper-mini-app` и PostgreSQL.
4. В настройках Mini App возьми фактический URL Mini App вида `https://gym-helper-mini-app.onrender.com`. Если Render добавил суффикс, замени его в `render.yaml` и локальном `.env`.
5. В локальном `.env` задай:

```env
WEBAPP_PUBLIC_URL=https://gym-helper-mini-app.onrender.com
```

6. В локальном `.env` задай также `PUBLIC_SITE_URL=https://gym-helper-public-site.onrender.com`.
7. Скопируй `DATABASE_URL` из Render в локальный `.env`, чтобы бот, сайт и Mini App использовали одну PostgreSQL-базу.
8. Перезапусти Telegram-бота. Он заново установит кнопку Mini App через Bot API.

`onrender.com` может добавить суффикс, если имя занято — используй фактический URL сервиса. После публикации проверь `/healthz` у обоих сервисов.

## Временный тест без деплоя

LocalTunnel подходит только для короткого теста. Если локальный процесс или туннель остановился, ссылка снова начнёт отдавать 503. Для друга надёжнее использовать Render.

## Безопасность

- В Render не загружай `.env` в репозиторий.
- `BOT_TOKEN`, `DEEPSEEK_API_KEY`, `ADMIN_KEY` и строка базы должны храниться только в Secrets/Environment Variables.
- `DEEPSEEK_API_KEY` нужен для текстовой генерации; распознавание изображений настраивается отдельно через vision-compatible API, потому что DeepSeek Chat не анализирует фото напрямую.
- Owner Dashboard не включён в публичный демо-режим и требует ключ владельца в рабочем режиме.

## Если Render пишет `Failed to build pillow` и `KeyError: __version__`

В проекте закреплён Python 3.12 через `runtime.txt`, а Pillow обновлён до совместимой версии. В Render после изменения файлов нажми **Manual Deploy → Clear build cache & deploy**. Если Render использует старый commit, выбери ветку `main` и запусти deploy заново.

## Если Render пишет `metadata-generation-failed` для `pydantic-core`

Это возникает из-за старого ограничения `pydantic<2.6`, для которого pip пытается собрать несовместимый `pydantic-core`. Ограничение обновлено до `pydantic>=2.10,<3`, где для Python 3.12 используется готовый wheel. В Render снова выбери **Manual Deploy → Clear build cache & deploy**.
